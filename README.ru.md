# VisualFlow Studio

**Self-hosted пространство для генерации, последовательной доработки, просмотра и скачивания изображений и видео через Google Flow.**

Версия **1.1.2.33** · [English](README.md) · [Развёртывание](DEPLOYMENT.ru.md) · [Участие в разработке](CONTRIBUTING.ru.md)

> [!IMPORTANT]
> VisualFlow Studio — неофициальный независимый проект сообщества. Он не связан
> с Google и не поддерживается Google. Система управляет веб-интерфейсом Flow
> через настоящий браузер и может потребовать обновления после изменений Flow.
> Владелец установки отвечает за аккаунт, кредиты, материалы и соблюдение правил.

## Зачем нужен VisualFlow Studio

Google Flow рассчитан на интерактивную работу в браузере. VisualFlow Studio
добавляет self-hosted слой для команды дизайнеров: единую веб-панель,
сохраняемые задания, локальное хранение результатов, понятные ошибки и
последовательную доработку без выдачи пользователям терминала или RDP.

Дизайнер может создать изображение товара, открыть результат, добавить новые
референсы, описать изменения, получить следующую пронумерованную версию,
сравнить её в галерее и скачать оригинал либо вариант 2K.

## Происхождение проекта

VisualFlow Studio вырос из production-прототипа и двенадцати дней плотной
работы над реальными задачами команды дизайнеров: отказ от постоянного RDP,
удобная панель, референсы, версии доработок, надёжное скачивание,
восстановление, очистка и защита эксплуатации. Проект опубликован как open
source, чтобы проделанная работа не пропала в закрытой разовой установке, а
могла развиваться вместе с сообществом.

## Возможности

### Изображения

- генерация по текстовому описанию через Google Flow;
- до 10 загруженных референсов в одном задании;
- последовательная доработка результата с нумерацией версий;
- выбор модели, пропорций и количества результатов;
- миниатюры референсов, ручной слайдер и увеличенный просмотр;
- просмотр результатов с навигацией, скачиванием, доработкой и удалением;
- оригинальный PNG и подготовка версии 2K средствами Flow;
- повтор ошибки с тем же промптом, настройками и сохранёнными референсами;
- проверка перед отправкой, что фактический запрос Flow содержит промпт,
  выбранную модель и все ID референсов;
- постоянный статус отправки, понятные ошибки и копирование диагностики;
- сворачивание длинных промптов и кнопка копирования наверху.

### Видео

- Text-to-Video с поддерживаемыми моделями Veo и форматами;
- сохранение состояния и восстановление после перезапуска;
- автоматическое скачивание через страницу готового медиа;
- маркировка 720p для тарифов без более высокого разрешения;
- восстановление созданных, но не скачанных клипов из каталога gflow;
- локальная обрезка и склейка через FFmpeg;
- совместная очистка устаревших файлов и записей базы.

### Эксплуатация

- FastAPI и адаптивная веб-панель;
- SQLite и локальное либо S3-совместимое хранилище;
- Docker с Chrome, Xvfb, FFmpeg и непривилегированным пользователем;
- закрытый постоянный профиль Chrome вне образа;
- последовательный доступ к профилю, защищающий его от повреждения;
- health check, структурированные логи, backup, Nginx, TLS и Fail2ban;
- legacy-код мультиаккаунтинга и прокси отделён от основного провайдера.

## Чем проект не является

- Это не официальный Google API и не средство обхода лимитов.
- Репозиторий не содержит аккаунтов, подписок, cookies, кредитов или прокси.
- Работа после любых будущих изменений интерфейса Flow не гарантируется.
- Проект не даёт прав на чужие материалы. Загружайте только разрешённый контент.

## Архитектура

```text
Браузер дизайнера
      │ HTTPS + авторизация
      ▼
Nginx / reverse proxy
      │ 127.0.0.1:4000
      ▼
VisualFlow Studio (FastAPI)
      ├── веб-панель и REST API
      ├── каталог заданий SQLite
      ├── локальное/S3-совместимое хранилище
      ├── обработка FFmpeg
      └── gflow-cli → Playwright → системный Chrome → flow.google.com
                              │
                              └── постоянный закрытый профиль Chrome
```

Задания одного профиля выполняются последовательно. Для параллельной работы
нужны независимые авторизованные профили. Несколько процессов Chrome нельзя
запускать на одном каталоге профиля.

## Требования

- Linux x86-64; production проверялся на Ubuntu 24.04 LTS;
- Docker Engine и Docker Compose v2;
- минимум 4 ГБ RAM, рекомендуется 8 ГБ;
- Google-аккаунт с законным доступом к Flow и достаточными кредитами;
- один интерактивный вход для создания профиля Chrome.

Python 3.11, Chrome, Xvfb, Node.js и FFmpeg входят в production-образ.

## Быстрый старт

### 1. Клонирование и настройка

```bash
git clone https://github.com/The88788/VisualFlow-Studio.git
cd visualflow-studio
cp config/setting.example.toml config/setting.toml
```

```toml
[generation]
provider_mode = "gflow"
max_concurrent_videos = 1

[gflow]
home = "/app/gflow_profiles"
profile = "client"
project_id = "YOUR_FLOW_PROJECT_UUID"
executable = "/usr/local/bin/gflow"
timeout = 1200
```

### 2. Авторизация профиля

В графической сессии выполните
`gflow auth login --profile client --browser chrome`, завершите вход в Flow,
корректно закройте Chrome и поместите `profile_client` в `gflow_profiles/`.

Профиль содержит действующую Google-сессию. Не добавляйте его в Git, не
передавайте другим людям, не включайте в образ и не публикуйте через веб-сервер.

### 3. Сборка и запуск

```bash
docker compose -f docker-compose.prod.yml build
docker compose -f docker-compose.prod.yml up -d
curl http://127.0.0.1:4000/health
```

```json
{"status":"ok","service":"VisualFlow Studio","version":"1.1.2.33"}
```

Production открывает порт только на `127.0.0.1:4000`. Внешний доступ должен
идти через HTTPS reverse proxy с авторизацией. См. [DEPLOYMENT.ru.md](DEPLOYMENT.ru.md).

## Основные настройки

| Секция | Параметр | Назначение |
|---|---|---|
| `generation` | `provider_mode` | `gflow` для актуального Flow |
| `generation` | `max_concurrent_videos` | Параллелизм приложения |
| `gflow` | `home` | Каталог закрытых профилей |
| `gflow` | `profile` | Имя профиля gflow |
| `gflow` | `project_id` | Существующий проект Flow |
| `gflow` | `timeout` | Тайм-аут команды провайдера |
| `cleanup` | `max_age_days` | Срок хранения результатов (по умолчанию: 60 дней) |
| `cleanup` | `tmp_max_hours` | Срок хранения временных файлов |
| `ip_whitelist` | `enabled`, `ips` | Ограничение по IP |

Актуальный шаблон: [`config/setting.example.toml`](config/setting.example.toml).
`config/setting.toml` нельзя добавлять в Git.

Для необязательного legacy-режима с refresh token также нужны переменные
окружения `VEOAPI_GOOGLE_OAUTH_CLIENT_ID` и
`VEOAPI_GOOGLE_OAUTH_CLIENT_SECRET`. Не сохраняйте OAuth-реквизиты в TOML,
Compose-файлах, Docker-образах или Git.

## Основные API-маршруты

На защищённой установке OpenAPI доступен по `/docs`.

| Метод | Endpoint | Назначение |
|---|---|---|
| `GET` | `/health` | Состояние и версия |
| `GET` | `/api/dashboard/data` | Данные панели |
| `POST` | `/api/images` | Создание или доработка изображения |
| `POST` | `/api/images/{id}/retry` | Повтор ошибочного задания |
| `GET` | `/api/images/{id}` | Состояние задания |
| `GET` | `/api/images/{id}/download/{index}` | Скачать оригинал |
| `POST` | `/api/images/{id}/upscale/{index}?scale=2k` | Подготовить 2K |
| `GET` | `/api/images/{id}/download/{index}/2k` | Скачать 2K |
| `DELETE` | `/api/images/{id}` | Удалить файлы и запись |
| `POST` | `/api/videos` | Создать видео |
| `GET` | `/api/videos/{id}` | Состояние видео |
| `GET` | `/api/videos/{id}/download` | Скачать MP4 |

```bash
curl -X POST http://127.0.0.1:4000/api/images \
  -F 'prompt=Предметная фотография товара на тёмном фоне' \
  -F 'model=nano2' -F 'aspect=4:3' -F 'count=1' \
  -F 'references=@./product.png'
```

## Безопасность перед публикацией

1. Оставьте порт 4000 на loopback, HTTPS завершайте на reverse proxy.
2. Закройте панель авторизацией: это не анонимный публичный endpoint.
3. Не публикуйте `config/`, `data/`, `logs/`, `browser_profiles/` и
   `gflow_profiles/`.
4. Не коммитьте cookies, пароли, ключи, прокси, клиентские медиа, SQLite,
   incident bundles, HAR-файлы и отладочные скриншоты.
5. Перед переводом private → public проверьте всю историю Git. Удалённый секрет
   остаётся в истории и требует ротации.

См. [SECURITY.ru.md](SECURITY.ru.md).

## Провайдеры и лицензии

Основной режим использует
[`gflow-cli`](https://github.com/ffroliva/gflow-cli), неофициальный инструмент
под MIT. Сборка применяет проверяемые по версии патчи совместимости и
останавливается, если ожидаемая структура зависимости изменилась.

Legacy-провайдер может использовать CloakBrowser. Его обёртка имеет MIT, но
загружаемый Chromium-бинарник лицензируется отдельно; клиентский браузерный
API/SaaS может требовать OEM/SaaS-лицензию. Бинарник не входит в репозиторий.

См. [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
