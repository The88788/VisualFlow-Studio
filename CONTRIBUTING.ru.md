# Участие в разработке VisualFlow Studio

[English](CONTRIBUTING.md)

Спасибо за помощь проекту. VisualFlow Studio автоматизирует изменяемое
стороннее веб-приложение, поэтому небольшие проверяемые изменения ценнее
широких переписываний без фактических данных.

## Перед созданием issue

- Проверьте существующие issue и укажите версии VisualFlow Studio и gflow-cli.
- Удалите email, cookies, пути профилей, подписанные URL, приватные промпты и
  клиентские изображения.
- Для ошибки провайдера приложите публичный код и очищенные технические детали.
  Никогда не публикуйте профиль Chrome, Cookies DB, HAR или incident bundle без
  ручной проверки каждого поля.
- Укажите, используется ли `flow.google.com`, выбранную модель и наличие
  референсов.

Уязвимости и утечки отправляйте через GitHub Security Advisories, а не
публичные issue. См. [SECURITY.ru.md](SECURITY.ru.md).

## Окружение разработчика

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
npm install
python -m unittest discover -s tests -p 'test_*.py' -v
python -m compileall src scripts
```

Windows:

```powershell
.\.venv\Scripts\Activate.ps1
```

При изменении провайдера также соберите Docker-образ. Build-time patcher должен
успешно примениться к закреплённой версии gflow-cli.

## Pull request

1. Создайте отдельную ветку под одну задачу.
2. Не добавляйте секреты и сгенерированные файлы.
3. Добавьте или обновите тесты.
4. Обновите английскую и русскую документацию.
5. Укажите, может ли изменение расходовать кредиты Flow.
6. Отделите реальную проверку от mock/unit-тестов.
7. Сохраните fail-closed проверки модели, промпта, референсов, разрешённых
   download-хостов и целостности файлов.

Не ослабляйте молча защиту профиля, авторизации, allow-list, размера файлов или
расходования кредитов.

## Коммиты

Краткий заголовок допускается на русском или английском. Несвязанный cleanup
выносите отдельно:

```text
Исправлена проверка референсов перед генерацией
Add persistent image retry status
```

## Где особенно нужна помощь

- тесты совместимости провайдера на очищенных fixtures;
- доступность и адаптивность панели;
- изоляция нескольких профилей без совместного Chrome-каталога;
- автоматизация установки и воспроизводимый deploy;
- наблюдаемость, восстановление и корректная очистка;
- переводы и документация;
- изоляция или удаление устаревшего legacy-кода.

Отправляя вклад, вы соглашаетесь с MIT проекта и подтверждаете право передать
этот код.
